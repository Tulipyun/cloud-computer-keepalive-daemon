# v0.2 protocol hardening

Status: implementation complete, 96-hour soak test passed

Baseline: `v0.1.0` / commit `d0fdfe6`

Development branch: `codex/v0.2-protocol-hardening`

## Goals

- Treat a remote desktop session as healthy only after display protocol evidence is observed.
- Implement complete SPICE ACK window handling instead of ACK_SYNC only.
- Propagate display subchannel failures to the owning session.
- Separate authentication, maintenance, network, protocol, and local configuration failures.
- Retry with a policy appropriate to the failure instead of re-login on every disconnect.
- Keep the verified v0.1.0 behavior available as a frozen fallback.

## Implemented changes

### SPICE flow control

- Raw ZTE channels now retain SET_ACK generation and window values.
- ACK_SYNC is sent immediately after SET_ACK.
- A normal ACK is sent after each negotiated message window.
- ACK state is independent for each ZTE raw channel and each SCG Chuanyun channel.
- PING/PONG and ZTE `0x74 -> 0x79` replies now return write errors to the session owner.

### Display readiness

- ZTE display links 5 and 7 are tracked independently.
- DISPLAY_INIT write success is recorded per display link.
- MARK, SURFACE_CREATE, and DRAW_COPY are observed as display readiness evidence.
- A ZTE session fails if no display readiness evidence appears within 30 seconds.
- The session fails when all authenticated display channels close.
- SCG `SpiceOK` now requires display MARK readiness instead of MAIN_INIT alone.

### Connection processing

- ZTE and SCG loops ignore only real network timeouts.
- EOF, connection reset, malformed frames, and write errors terminate the current session and enter retry handling.
- The SCG loop continuously drains protocol frames; SOHO heartbeat remains on an independent 25-second schedule.
- The old SCG one-byte connection probe was removed because it could consume the first byte of a framed message.

### Heartbeat validation

- SOHO heartbeat responses are checked for accepted business codes.
- A single heartbeat failure is tolerated.
- Three consecutive heartbeat failures terminate the current protocol session.
- A successful heartbeat resets the failure counter.

### Retry policy

- Authentication/session failures trigger credential refresh and short retry delays.
- Platform maintenance and 502/503/504 failures use a slower delay capped at 5 minutes.
- Network failures use short exponential backoff capped at 2 minutes.
- Protocol/readiness failures use a separate backoff capped at 2 minutes.
- Local configuration failures stop automatic retries instead of looping forever.
- Retry delays include up to 20 percent jitter and can be interrupted with Ctrl+C.
- A session stable for more than 10 minutes resets accumulated failure counters.
- Re-login automatically reuses the configured userServiceId when multiple desktops exist.

## Deliberately not included

The Python project's synthetic ZTE display type=3 traffic at approximately 21 Hz is not enabled. It needs an independent capture confirming direction, idle cadence, counter semantics, and long-term bandwidth impact before it can become a default protocol behavior.

DISPLAY_INIT and INPUT_INIT are not periodically resent on the main channel. Initialization remains tied to the authenticated target subchannel.
